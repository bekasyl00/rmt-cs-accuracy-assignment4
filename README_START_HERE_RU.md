# Готовая работа и проверка

Здесь два завершённых этапа: исходные 120 ответов трёх коммерческих ИИ и 120 новых локальных результатов сравнения. Старые ответы сохранены. Новые результаты: keyword search 4/40 полностью верных, локальный Qwen без документов 4/40, Qwen с BM25-документами 6/40. Слабые результаты не исправлялись и не удалялись.

## Что запускать для проверки

Нужен Python 3.12 или новее. Распакуйте пакет, откройте Terminal в этой папке и выполните:

```bash
python3 -m venv .venv-check
source .venv-check/bin/activate
python reproduce_all.py --verify
```

В Windows активация: `.venv-check\Scripts\activate`. Установка MLX или скачивание модели для проверки НЕ нужны. Скрипт пересчитает старые и новые таблицы, статистические проверки, диагностику и графики из сохранённых ответов и оценок. Он должен завершиться строкой `PASS` с числом проверенных файлов.

## Что записать после вашей независимой проверки

Член команды, который действительно выполнил эти команды, записывает своё имя, дату, ОС и версию Python, использованный commit/tag, команды и результат. Это нужно для Appendix C. Автоматическая проверка уже выполнена, но она не заменяет ваш личный запуск. Бланк: `TEAMMATE_REPRODUCTION_RECORD.md`.

## Что внутри

- `data/` — исходные вопросы, ответы трёх ИИ, оценки и источники.
- `results/` — исходные пять таблиц; `diagnostics/` — дополнительные проверки старых данных.
- `supplement/raw/answers.jsonl` — все 120 реальных новых выходов, тексты запросов, найденные фрагменты, время, токены и ошибки.
- `supplement/raw/ratings.jsonl` — все 120 новых оценок с объяснениями. Оценивание AI-assisted; человеческое согласие оценщиков не выдумывалось.
- `supplement/results/` — новые таблицы, пять парных тестов с поправкой Холма, интервалы, ошибки, время и чувствительность.
- `supplement/figures/` — два новых графика.
- `supplement/protocol/` — протокол, история изменения плана ДО первых новых ответов, хэши, точные зависимости.
- `supplement/corpus/manifest.json` — 56 официальных источников и контрольные суммы корпуса.

## Новый запуск модели

Это отдельная, более долгая операция. Она НЕ нужна для подтверждения чисел в отчёте. На Apple Silicon установите зависимости из `supplement/protocol/requirements-generation.txt`, восстановите корпус с `build_corpus.py`, получите фиксированную ревизию модели, затем запускайте `run_experiment.py` в НОВЫЙ файл через `--output`. Существующий `answers.jsonl` нельзя перезаписывать; повторный запуск без нового пути просто пропускает уже сохранённые записи.

Новые ответы могут отличаться на другом runtime/GPU. Не переносите старые оценки автоматически на новые ответы — их нужно оценить заново. Для повторения с точными локальными входами корпус включён в ZIP; модель 1,6 ГБ в архив не включена.

## Честно объявленные ограничения

Предварительной загрузки протокола в Moodle не было. Новый протокол и переход к одному детерминированному прогону зафиксированы до первых дополнительных ответов, но Moodle submission и approval преподавателя не заявлены. Это Data Analytics исследование, поэтому один детерминированный прогон с 95% интервалами использован вместо искусственного SD по одинаковым seeds. Банк вопросов уже использовался; он не называется новым нетронутым test set.
